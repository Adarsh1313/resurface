# Resend email setup

Resurface sends these emails, all built on one shared branded template (`backend/src/lib/email-templates.ts`):

- **Waitlist confirmation:** `POST /v1/waitlist` sends it as soon as a new email joins the waitlist.
- **Private beta invite:** sent from `/dashboard/admin` via `POST /v1/admin/waitlist/:id/invite`.
- **Digest:** sent on schedule via `POST /v1/cron/tick` (see [cron-setup.md](./cron-setup.md)), or
  on demand from the dashboard via `POST /v1/digest/send-now`.
- **Reminder:** sent on schedule via `POST /v1/cron/tick` when a bookmark's `reminder_at` passes.

Digest and reminder emails include signed one-click **Open / Mark reviewed / Snooze 1 day** buttons.
Users can turn digest or reminder emails off under **Settings → Notifications**
(`/dashboard/settings?section=notifications`, backed by `GET/PATCH /v1/preferences`).

## Owner-only $0 mode (no domain)

With a free Resend account and **no verified domain**, Resend only delivers to the email address
you signed up to Resend with. Any other recipient is rejected (HTTP 403 in the logs). That's
enough when you are the only user:

1. Sign up at <https://resend.com> with the email you want digests to go to, for example
   `you@gmail.com`.
2. Create an API key under **API Keys**, with sending access.
3. On Render, set:

   ```env
   RESEND_API_KEY=re_...
   EMAIL_FROM=Resurface <onboarding@resend.dev>
   PUBLIC_APP_URL=https://your-web-app.vercel.app
   ```

   `onboarding@resend.dev` is Resend's shared test sender and works without a domain in this mode.
4. **Register in Resurface with that same email address.** Digests and reminders are sent to the
   Resurface account email, so it has to match the Resend account email or Resend will refuse them.
5. Add the cron-job.org job from [cron-setup.md](./cron-setup.md) so digests and reminders actually fire.

Limits: Resend's free tier allows 100 emails a day and 3,000 a month, which is far more than one
user needs. Waitlist and invite emails to *other* people won't deliver in this mode. Verify a domain
when you need that.

## Using a verified domain (for other users)

Set these on the Render backend service:

```env
RESEND_API_KEY=re_...
EMAIL_FROM=Resurface <hello@your-verified-domain.com>
EMAIL_REPLY_TO=you@your-domain.com
PUBLIC_APP_URL=https://your-web-app.vercel.app
ALLOWED_ORIGINS=https://your-web-app.vercel.app
ADMIN_EMAILS=you@your-domain.com
REQUIRE_INVITE=true
CRON_SECRET=(auto-generated by render.yaml)
```

The backend uses Resend whenever `RESEND_API_KEY` is set. `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER` and
`SMTP_PASS` are only a fallback. If neither is configured, emails are just printed to the server
console, which is handy in local dev.

Domain checklist:

1. Add a sending domain in Resend. A subdomain such as `mail.your-domain.com` is usually cleaner than
   the root domain.
2. Add the SPF and DKIM DNS records that Resend shows you.
3. Click **Verify DNS Records** and wait until the domain status shows `verified`.
4. Set `EMAIL_FROM` to an address on that domain.
5. Send a test (waitlist signup or **Send digest now**) and confirm it appears under Resend's **Emails** page.

## Manual test flow

1. Log in and click **Send digest now**. In Render logs, look for `Resend delivered (id=...)`.
2. Click **Mark reviewed** in the email. You should land on `/action-done?result=reviewed`.
3. Trigger the scheduler by hand:
   `curl -X POST https://resurface-nclr.onrender.com/v1/cron/tick -H "Authorization: Bearer $CRON_SECRET"`.
4. Waitlist and invite (domain mode only): submit the landing-page form, then invite the entry from `/dashboard/admin`.
